# O Culto das Cinzas

Survival horror em terceira pessoa feito com **Three.js + Vite**, com visual low‑poly inspirado no PS2 (verde doentio + âmbar).
Este repositório contém o **Capítulo 1 — Hospital São Dimas** (véspera, 1934), o **Capítulo 2 — Fumaça** e o **Capítulo 3 — A Confraria**, jogáveis do início ao fim, e o **Capítulo 4 — Cidade Morta**, também jogáveis do início ao fim (beco → Rua do Comércio → relojoaria → Praça do Relógio → primeiro confronto com O Vigia → Torre do Relógio → casa das máquinas → segundo confronto com O Vigia → passagem do Relógio), e o **Capítulo 5 — Águas Negras**, também do início ao fim (canais, casa de bombas, energia, mezanino, antecâmara e **salão das turbinas** com o chefe **A Afogada**, galeria de descarga e tela de fim), e o **Capítulo 6 — O Acervo**, também do início ao fim (doca do Museu → átrio → Salão de Exposição → porta-cofre → Ala de Conservação → depósito → **Galeria do Colecionador** com o chefe **O Colecionador** → reserva técnica e tela de fim), e o **Capítulo 7 — Sob a Pedra**, também do início ao fim (poço da escada → galeria de pedra → ossuário com emparedados nos nichos → cripta do coveiro-mor → túnel → Estação Sé Velha → trilhos → **Linha Velha** além da grade acorrentada → cabine de sinalização (agulhas) → **Estação Sob a Pedra** com o chefe **O Vigia Caiado** → escada de serviço e tela de fim).

▶ **Jogar no navegador:** https://luispauloalves500.github.io/o-culto-das-cinzas/

> Documento de design completo: [`GDD.md`](GDD.md).

## Como rodar

```bash
npm install
npm run dev        # servidor de desenvolvimento
npm run build      # gera dist/
npm run preview    # serve o build
npm test           # testes unitários (Node)
npm run smoke      # teste de fumaça E2E no Chromium headless (precisa de Chrome em /usr/bin/google-chrome ou CHROME_PATH)
```

## Controles

| Ação | Teclado/mouse | Gamepad (layout padrão) |
|---|---|---|
| Mover / correr | WASD / Shift | analógico esq. / L3 |
| Câmera | mouse (clique na tela para capturar) | analógico dir. |
| Ataque leve / forte | botão esquerdo / botão direito | RB / RT |
| Revólver: atirar (mira automática) / coronhada | botão direito / botão esquerdo | RT / RB |
| Revólver: **mira manual** (segurar) e atirar | segurar Q + botão esq. ou dir. | segurar LT + RB/RT |
| Revólver: **recarregar** o tambor | T | direcional ↑ |
| **Reparar** a arma em mãos (kit / pedra de afiar) | G | direcional ↓ |
| Bloquear / esquivar | Q (com arma corpo a corpo) / Espaço | LT / B |
| Interagir / pular cena | E | A |
| Curar (bandagem) | H | X |
| Trocar arma (machado → martelo → facão → revólver → lança) | R | LB |
| Inventário e documentos | Tab | Y |
| Mapa (←/→ ou 1–4 troca de andar) | M | Back/Select |
| Pausa | Esc / P | Start |
| Depuração (hitboxes) | F3 | — |

Opções no menu: sensibilidade do mouse, inverter eixo Y, volume e escala de resolução (salvos no `localStorage`).

### Decisão narrativa — o Vigia (GDD × morte no Cap. 4)

O GDD previa o **"Retorno do Vigia"** como chefe do Cap. 7, mas neste jogo o Vigia **morre de verdade no Cap. 4** (como foi pedido). A solução mantém as duas coisas sem desfazer a morte: **ele continua morto** — e é isso que a Confraria usou. A *Guia de remoção* e a *Ata da Primeira Cinza* contam que os acólitos desceram o corpo pela Linha Velha até a Estação Sob a Pedra e o **emparedaram em cal**, como fazem com os "guardas" das catacumbas (os emparedados). O que volta não é o Vigia vivo, e sim **O Vigia Caiado**: o mesmo sobretudo, chapéu, gancho e lampião frio, mas coberto de cal, **cego** (os olhos foram selados) e guiado só pelo som — por isso a luta é sobre ruído, sinetas e investidas às cegas, e não repete o Vigia da praça. Quando ele cai, "o lampião frio apaga — de vez, agora". O GDD continua respeitado (o Vigia é o chefe do Cap. 7) e a morte do Cap. 4 não é anulada.

### Sobre modelos e texturas

Exceção: o **Elias REV6** (GLB do pacote do projeto, ver acima). Fora ele, não foram usados GLB/texturas de terceiros: **o visual é procedural** (geometria low‑poly montada em código, personagens com rig hierárquico animado por código, texturas desenhadas em `<canvas>`). Isso evita problemas de licença e mantém o build leve. Trocar por GLB rigados no futuro é possível sem mexer na lógica (os sistemas usam apenas a hierarquia de ossos do `ProceduralRig`).
